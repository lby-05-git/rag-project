# 头脑风暴：中文金融文档 RAG 系统

> **日期**: 2026-07-23
> **项目**: RAG 项目（rag-project）

---

## 项目目标

构建一个面向中文金融领域研究报告的检索增强生成（RAG）系统，能够对多份
PDF 研报进行智能检索、内容提取和问答交互，帮助投资研究人員快速从大量
研报中获取关键信息。

### 核心价值

- 将分散在多份 PDF 中的信息集中起来，支持跨文档检索
- 用自然语言问答替代手动翻阅和关键词搜索
- 保留来源追溯，确保生成结果可验证、可引用

---

## 核心功能

### MVP（最小可行产品）

1. **PDF 文档导入与解析**
   - 支持中文 PDF 研报的上传/加载
   - 提取文本内容，保留页码、标题等元数据
   - 处理 CJK 字符和金融专业术语

2. **文档分块与嵌入**
   - 可配置的分块策略（按段落/按章节/固定长度）
   - 生成向量嵌入并存储到向量数据库

3. **语义检索**
   - 支持自然语言查询，返回最相关的文档片段
   - 显示检索结果的来源（文件名、页码）

4. **问答生成**
   - 基于检索结果生成中文回答
   - 回答中引用来源，支持追问

### 进阶功能（后续迭代）

5. **批量分析**：一次查询多份报告并生成对比摘要
6. **数据看板**：展示导入统计、查询热力图、检索质量指标
7. **增量更新**：新增 PDF 自动增量索引，无需重建全部

---

## 技术约束

### 语言与运行时
- **Python 3.12+** 作为主要开发语言
- 使用 `pytest` 进行测试

### 数据与存储
- 原始 PDF 存放在 `data/` 目录（不纳入版本控制）
- 向量数据库：待选型（如 Chroma、FAISS、Qdrant 等）
- 嵌入模型：需支持中文的双语/多语言模型（如 `text2vec-large-chinese`、
  `BAAI/bge-m3` 等）
- LLM 后端：通过 API 调用（如 Claude API、OpenAI API）或本地部署

### 文档处理
- PDF 解析库需支持 CJK 字符集（如 PyMuPDF、pdfplumber）
- 分块策略需考虑中文句子边界和金融术语完整性

### 质量要求
- **测试优先**：每个组件都需编写测试
- **可追溯性**：每个生成结果必须追溯到来源文档和页码
- **模块化**：导入、分块、嵌入、检索、生成各组件独立可替换

## 用户故事

### US1 — 研报检索问答（P1 - MVP）

**作为** 投资研究人员，
**我希望** 用自然语言提问关于某份研报的内容，
**以便** 快速找到我需要的信息，而不用通读整份 PDF。

**验收场景**：

1. **Given** 系统中已导入宁德时代研报，
   **When** 我提问"宁德时代 2025 年营收预测是多少"，
   **Then** 系统返回相关段落和对应的摘要回答，并标注来源页码。

2. **Given** 系统中有多份不同券商的研报，
   **When** 我提问"各券商对贵州茅台的评级有何差异"，
   **Then** 系统汇总多家观点并逐一标注来源。

### US2 — 跨文档对比分析（P2）

**作为** 投资研究人员，
**我希望** 对比多份研报对同一指标的不同预测，
**以便** 快速了解市场分歧和共识。

**验收场景**：

1. **Given** 系统中有 3 份关于宁德时代的研报，
   **When** 我提问"各券商预测的 2026 年净利润对比"，
   **Then** 系统以表格形式展示各家预测值及其来源。

### US3 — 研报管理与索引更新（P3）

**作为** 系统管理员，
**我希望** 能够添加新研报并自动索引，
**以便** 知识库保持最新。

**验收场景**：

1. **Given** 系统中已有索引，
   **When** 我放入一份新的 PDF 研报，
   **Then** 系统自动完成解析、分块和嵌入，无需手动操作。

## 进阶调优需求

### 检索质量优化
- **分块策略调优**：对比不同分块大小（256/512/1024 tokens）和重叠率
  对检索精度的影响
- **混合检索**：结合关键词检索（BM25）和语义检索，提高召回率
- **重排序（Reranking）**：对初检结果进行重排序，提升 Top-K 精度

### 生成质量优化
- **提示工程**：针对金融问答场景设计专用 System Prompt
- **幻觉检测**：自动检查生成内容是否与检索结果一致
- **结构化输出**：对比较类问题输出表格/结构化格式

### 性能优化
- **异步流水线**：文档导入和嵌入使用异步处理，提高吞吐量
- **缓存策略**：对高频查询结果进行缓存
- **批处理**：批量文档导入时优化嵌入生成效率

### 可观测性
- **检索质量仪表盘**：实时监控 Hit Rate、MRR、NDCG 等指标
- **查询日志**：记录每次查询的耗时、检索结果和生成质量评分
- **A/B 测试框架**：支持对比不同嵌入模型/分块策略的效果差异
